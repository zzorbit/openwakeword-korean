# 웹 화면에서 한국어 호출어 학습하기

Windows에서는 Python을 설치한 뒤 [저장소 ZIP](https://github.com/zzorbit/openwakeword-korean/archive/refs/heads/main.zip)을 내려받아 압축을 풀고 `scripts/Start-Web.cmd`를 더블클릭합니다. Python 3.12를 권장합니다.

라이브러리 설치 파일을 포함한 실행 폴더를 받았다면 그 폴더의 `Start-Web.cmd`를 더블클릭합니다.

첫 실행에는 인터넷 연결이 필요합니다. 실행 파일은 폴더 안에 `.venv`를 만들고 웹 화면에 필요한 패키지를 설치합니다. 다운로드 캐시와 임시 파일은 작업 폴더의 `storage/runtime_cache`에 둡니다. 설치가 끝나면 브라우저에서 학습 화면이 열리고, 이후에는 같은 파일로 설치된 환경을 바로 실행합니다. 설치가 중단되면 창에 표시된 내용을 확인한 뒤 같은 파일을 다시 실행하세요.

명령으로 설치했다면 `koww web`을 실행합니다. 가상환경을 활성화하지 않았다면 저장소 폴더에서 다음을 사용하세요.

```powershell
. .\scripts\Use-ProjectStorage.ps1
.venv\Scripts\python.exe -m korean_openwakeword web
```

학습 화면의 기본 주소는 `http://127.0.0.1:8793/`입니다. 학습 화면을 사용하는 동안 실행 창을 열어 두세요. 작업 폴더를 직접 고르려면 `koww web --workspace D:\wakeword-work`처럼 지정합니다.

웹 서버를 종료하려면 `scripts/Stop-Web.cmd`를 더블클릭합니다. 별도 작업 폴더로 열었다면 `Stop-Web.cmd -Workspace "D:\wakeword-work"`처럼 같은 폴더를 지정합니다. 생성·학습 작업도 멈추려면 웹 화면에서 먼저 **일시정지**를 누르고 정지가 완료된 뒤 서버를 종료하세요.

웹 화면은 어두운 회청색 배경에 **한 화면에서 한 가지 일을 하는 방식**입니다. 현재는 일반적인 PC 모니터에서의 배치를 우선합니다. 호출어 입력부터 마이크 시험까지 단계별 화면으로 나누며, 짧은 제목 아래에 지금 할 일이나 진행 중인 작업을 한 문장으로 안내합니다. 새 호출어도 같은 공통 레이아웃을 사용합니다. 진행률은 서버에서 받은 실제 처리 상태를 표시합니다.

처음 열거나 새로고침하면 기존 챕터와 같은 배경에 **화면을 불러오는 중...**과 점 애니메이션을 표시합니다. 필요한 목록·검수 영역의 높이·글꼴과 최종 배치가 준비된 뒤 본문을 공개합니다. 준비가 실패하면 오류와 다시 불러오기 버튼을 표시하며, 저장된 작업은 유지합니다.

하단의 **이전·다음**은 화면 이동, 중앙의 **일시정지·재개**는 작업 제어에 사용합니다. 필요한 처리·입력·검수가 끝나기 전에는 다음이 비활성 상태입니다. 왼쪽 색인은 진행한 단계까지 유지되며, 앞 단계로 돌아가도 진행 위치로 바로 이동할 수 있습니다. 양방향 이동 안내는 완전히 나타난 뒤 최소 **0.8초** 유지합니다. 화면과 이동 안내의 등장·퇴장 효과는 각각 **0.15초**입니다. 다음 본문과 검수 목록·프레임 높이·배치가 실제로 준비될 때까지 이동 안내를 유지한 뒤 화면을 공개합니다. 준비 시간은 고정 지연과 별개이며, 다음 챕터를 먼저 보여 준 뒤 목록을 뒤늦게 붙이지 않습니다. 설정·작업 기록·모델 목록은 보조 메뉴에서 엽니다.

오른쪽 상단의 **설정**을 누르면 **새 호출어 생성**, **작업한 호출어** 전환, **세부 설정**, **작업 기록**을 한 메뉴에서 사용할 수 있습니다. 메뉴 바깥을 클릭하거나 Esc를 누르면 닫힙니다. 각 단계 제목 아래에 호출어와 학습 규모를 반복 표시하지 않습니다. 현재 모델은 설정 메뉴의 작업한 호출어에서, 저장된 호출어와 학습 규모는 처음 두 화면에서 확인합니다.

왼쪽 색인은 현재 챕터를 고정 강조하지 않습니다. 마우스를 올린 막대와 주변 막대만 **36·23·14·7px**의 짧은 네 단계 길이로 커지고, 마우스를 벗어나면 기본 길이로 돌아갑니다. 키보드로 색인에 초점을 옮겨도 같은 표시를 확인할 수 있습니다.

완료한 화면도 호출어 입력칸·학습 규모·다운로드 목록·처리 수량·검수 판정을 그대로 보여줍니다. 호출어와 규모는 바꿀 수 없으며, 저장된 검수 음원은 다시 들을 수 있습니다. 과거 화면을 열어도 작업이나 승인을 다시 실행하지 않습니다. 기록이 없는 수량은 100%로 채우지 않고 내역이 없다고 표시합니다.

## 처음 선택할 것

호출어와 **동작 확인용 / 시험 모델용 / 상용 모델용** 중 하나를 고릅니다. 처음에는 동작 확인용을 권합니다. 수치는 작업량 예시이며 성능을 보장하는 설정이 아닙니다. 세부 설정에서 호출어 수·증강 횟수·학습량·비호출 시간을 바꿀 수 있습니다.

새 모델은 **호출어 입력 → 학습 규모 선택 → 준비 자료** 순서로 설정합니다. 다음으로 넘어가 모델을 만든 뒤, 다운로드 화면에서 **다운로드 시작**을 누르세요. 다운로드·검사·전처리·자료 연결을 마쳐야 하단의 **다음**이 활성화됩니다. 파일 전송이 100%여도 검사나 연결이 남아 있으면 기다립니다. 기존에 시작한 학습에는 새 이동 대기를 자동으로 추가하지 않습니다.

저장 폴더는 입력하지 않습니다. 새 학습은 작업 폴더의 `models/model_0001`, `models/model_0002`처럼 번호가 붙은 폴더를 사용하며, 저장될 전체 경로를 화면에 표시합니다. 같은 호출어·작업 규모·작업량·평가 기준이면 기존에 등록한 학습을 이어서 엽니다. 평가 기준이 바뀌면 새 학습을 만들고, 이전 학습은 모델 목록에서 그대로 열 수 있습니다. 이전 한글 폴더를 포함해 기존 학습 폴더는 이동하거나 이름을 바꾸지 않습니다. 작업 폴더의 `shared`와 `cache`는 여러 모델 학습에서 재사용합니다.

**준비 자료**는 학습용과 성능 평가용으로 나누어 종류·목표 분량·출처를 보여줍니다. 긴 목록은 페이지로 나누고, 세부 설정에서 임시 공간을 포함한 저장 용량의 참고 계산을 확인할 수 있습니다. 무손실 FLAC의 실제 보관량은 변환 후 확인하며, 참고 계산은 실제 필요 용량이나 최소 용량이 아닙니다.

동작 확인용·시험 모델용은 소음 증강에 AudioSet 일부·FMA와 한국어 원본 음성을 사용합니다. 상용 모델용은 별도 증강 묶음 대신 학습용 일반·한국어 비호출 원본을 재사용합니다. 세 규모 모두 MIT RIR을 사용하며, 공통 평가는 별도 Seoul·MUSAN·FSD50K·OpenSLR28 자료로 구성합니다. 일부만 사용해도 원본 묶음 전체를 다운로드해야 할 수 있습니다. Qwen 가중치 용량은 별도이며, 이미 검증한 파일은 재사용합니다. 자료 이용 조건은 준비 자료의 출처 안내에서 확인합니다.

새 프로젝트는 규모에 맞는 자료를 자동 선정합니다.

| 규모 | 일반 비호출 | 한국어 비호출 |
| --- | --- | --- |
| 동작 확인용 | 공개 특징 약 2,000시간 | Zeroth 1시간 |
| 시험 모델용 | 공개 특징 약 2,000시간 | YODAS2 약 667시간 |
| 상용 모델용 | AudioSet 1,500시간·MLS 1,500시간·FMA full 500시간 | YODAS2 1,500시간 |

FMA full은 필요한 원곡만 선택 다운로드하고, 자동 준비에서는 검증한 학습용 FLAC을 보관합니다. 상용 모델용에는 사용하지 않는 기존 2,000시간 특징 파일과 학습용 Zeroth를 추가로 받지 않습니다. 평가용 Zeroth 등 공통 평가 자료는 별도로 준비합니다. 실제 준비량과 검사 후 연결한 양을 구분하며, 학습 배치의 일반·한국어 비중은 **75:25**를 유지합니다.

새로 준비하는 공개 학습 음원 변환본은 **기존 학습 입력과 동일한 16kHz 모노 PCM16을 무손실 FLAC으로 보관**합니다. 검증한 새 대규모 비호출 원본과 중복 WAV만 정리하고, 공식 예제의 공유 기본 묶음·기존 자료·생성 TTS·평가 WAV는 보존합니다. FLAC 보관 방식 자체는 선택한 자료 시간과 학습 설정, 다운로드 전송량을 바꾸지 않습니다. 정리한 원본을 다른 설정으로 다시 변환하려면 재다운로드가 필요합니다. [저장 기준](STORAGE_POLICY.md#대규모-자료의-중복-저장-줄이기)을 참고하세요.

학습 도구 준비에서 CPU 또는 NVIDIA GPU를 선택합니다. 설치를 시작하기 전이나 설치에 실패한 경우, 다운로드 화면의 **연산 장치 변경**으로 돌아가 선택을 바꿀 수 있습니다. **다음**을 눌러 저장한 장치에 맞춰 현재 가상환경의 PyTorch와 TorchAudio를 준비하고, 그 장치로 음성을 생성하고 모델을 학습합니다. NVIDIA GPU를 선택하면 공통 평가용 ONNX Runtime과 CUDA 라이브러리도 프로젝트 캐시에 따로 준비합니다. 검증한 Windows x64·Python 3.12용 평가 도구는 약 1.43GB이며 설치에는 추가 임시 공간이 필요합니다.

## 화면에서 진행하는 순서

1. 선택한 목표에 맞춰 공개 원본 목록을 고정하고 다운로드·해시 검사·압축 해제·제공자 정보 연결·학습/개발 자료 분리를 진행합니다. 실제 전처리 길이가 부족하면 같은 계획의 다음 원본을 준비하며, 중복·실패 음원을 목표 시간으로 세지 않습니다.
2. 제공 학습·평가 배경 자료는 자동 검사 후 연결합니다. 직접 추가한 자료는 대표 음원을 듣고 검수합니다.
3. **기준 목소리 생성**에서 학습용 10개 분류와 공통 평가용 10개 분류의 첫 후보를 각각 **5개씩**, 총 **100개** 만듭니다. 성별·연령 분류 안에서 음높이·울림·음색·속도·억양과 난수 시드를 무작위로 정하는 방식은 동일합니다. 이미 완성한 첫 후보 묶음은 검증 후 재사용하고, 중단된 묶음은 저장한 계획과 시드로 이어갑니다. 생성 화면은 학습용 **50개**, 평가용 **50개**의 진행 상황을 각각 표시합니다. 이 수량은 최종 선택 수량과 다릅니다.

   준비가 끝나면 **기준 목소리 검수**로 이동해 분류마다 저장된 후보 5개를 바로 듣고 선택합니다. 후보 카드마다 실제 설정과 난수 시드를 표시하며, 재생 중인 카드를 강조합니다. 끝까지 듣지 않은 후보도 직접 선택할 수 있습니다. 선택과 실제 청취 기록은 별도로 저장하며 자동 선택이나 다음 후보 자동 재생은 하지 않습니다. 남성 어린이·청소년·청년·중년·노년, 여성의 같은 순서로 진행하고 학습용 10개 분류를 마친 뒤 공통 평가용 10개 분류를 검수합니다. 최종 선택 목표는 학습용 **동작 확인용 20개 / 시험 모델용 100개 / 상용 모델용 500개**, 학습과 분리한 공통 평가용 **30개**입니다.

   한 묶음에서 **0개부터 남은 목표 수량까지** 선택할 수 있습니다. 카드 오른쪽의 **+**를 누르면 같은 화면에서 새 후보 5개를 만들며, 이전에 선택한 목소리는 유지됩니다. 카드의 재생 버튼으로 재생·일시정지·이어 듣기를 하고, 묶음 제목 오른쪽에서 음량을 조절합니다. 카드 옵션은 **음높이·울림·음색·속도·억양**으로 짧게 표시합니다. 학습용은 분류별 **2개 / 10개 / 50개**, 공통 평가용은 분류별 **3개**를 채운 뒤 하단 **다음**으로 분류를 확정하고 이동합니다. 모든 분류를 확정하면 같은 **다음** 버튼으로 호출어 단계에 진입하며, 선택한 음원 자체가 이후 호출어 생성의 기준 목소리로 연결됩니다. 후보와 선택 기록은 프로젝트에 저장되며 원본 음원과 기존 검수 기록은 보존됩니다. 이미 학습을 진행했거나 완료한 모델은 기존 검수 방식과 기록을 유지합니다. ‘오늘은 창밖으로…’ 문장은 목소리 샘플이며 호출어 학습 음원이 아닙니다.

**평가 기준은 학습 규모와 별개로 동일합니다.** 새 공통 평가 v5는30음색·호출 원본2,000개의 일반 소음 시험32,000회에, 대표500개 원본의 일반·강한 잔향 시험16,000회를 더해 **총48,000회**를 시험합니다. 두 잔향 강도에 같은500개를 사용하며, 대응하는 잔향 없는 조건은 기본32,000회에서 비교합니다. 학습과 분리한 가상 공간20개·RIR80개를 사용하고 잔향별 결과도 구분합니다. 대표 원본은 음색·스타일 분포를 고르게 고정 seed로 선택하며, 이 수량이 검증된 최적값이라는 뜻은 아닙니다. 학습 음성1,000개를 선택해도 평가 기준은 줄이지 않습니다. 배경 다운로드와 완성된 평가 WAV는 검증 후 재사용하고, 기존 v1–v4 설정과 완료 결과는 변경하지 않습니다.

자료·표본·오호출 시험 시간이 부족하면 결과 화면에 이유를 표시합니다. 30시간은 다운로드·검수·채점이 모두 완료된 분량이 아니라 준비 기준입니다. 오호출 시험 초기화로 제외되는 시간은 같은 자료 목록의 미사용 원음으로 필요한 만큼 보충하고, 기본30시간·보충량·실제 채점 가능한 시간을 따로 표시합니다. 보충 원음은 호출어 혼합에 추가하지 않습니다. 짧은 배경을 반복해 공통30시간·최종100시간을 채우지 않습니다. 공통 평가는 모델 비교용이며, 독립 최종 평가는 모델·설정 동결 후 별도 자료로 진행합니다. [최종 평가 절차](LIBRARY_GUIDE.md#8-모델설정-확정-후-최종-평가하기)를 따르세요.

호출어 한 원본에서는 같은 배경 원본·구간으로 SNR 20·15·10·5·0 dB를 비교합니다. 같은 원본을 여러 세기로 사용해도 원본 수를 늘려 세지 않습니다. 실제 사용한 종류·원본·조건별 표본 수와 시험하지 못한 후보를 기록합니다. 자세한 구성과 분리 검증 범위는 [평가 자료 안내](DATASETS.md#성능-평가용-배경-음원)를 참고하세요.

호출어 본검수와 유사어 검수는 전체 생성 결과에서 대표 음원을 듣습니다. 검수 결과를 저장하면 서버가 근거를 확인하고 통과한 자료를 학습·평가에 연결합니다. 직접 추가한 자료도 검수합니다. 기준 목소리 후보 검수에서는 성별·연령에 맞고 서로 구분되는 목소리를 직접 선택하고, 모든 분류를 확정한 뒤 다음 단계로 진행합니다. 대표 음원 검수는 나머지 음원의 개별 청취를 대신하지 않습니다.

발음 검수 화면은 **목록 버튼·현재 번호·재생 바·부적합 버튼**의 간결한 구성으로 통일합니다. 펼친 목록의 높이는 실제 화면 여유에 맞추고 하단 이동 버튼을 가리지 않습니다. 목록 바깥 클릭과 Esc로 닫을 수 있으며 열고 닫을 때 재생부의 위치를 유지합니다. 연속 재생은 필수 검수의 마지막 음원에서 멈추고, 화면을 떠나면 재생을 멈춥니다.

호출어 본검수와 유사어 발음 검수는 실제 음원을 끝까지 청취해야 적합 판정과 다음 이동 조건을 충족합니다. 부적합 표시를 취소해도 듣지 않은 기록을 청취 완료로 만들지 않습니다. 별도 정상 버튼이나 검수 저장 버튼을 반복해서 누르지 않고 하단 **다음**으로 확정합니다. 직접 추가한 자료의 출처·내용 검수와 과거 프로젝트의 별도 검수 화면은 저장된 정책에 맞는 판정·사용 동의 방식을 유지합니다.

기준 목소리 후보는 다섯 개씩 묶어 보관합니다. 카드 왼쪽 화살표로 이전 후보를 다시 보고, 이미 생성된 다음 묶음이 있으면 오른쪽 화살표로 이동합니다. 마지막 묶음의 오른쪽에는 새 후보를 생성하는 **+**가 나타납니다. 묶음 이동은 저장된 음원을 조회하며, 선택과 청취 기록은 유지됩니다. 선택 개수는 분류 제목 바로 옆에 표시하고 음량은 맨 오른쪽에서 조절합니다.

자료 다운로드는 화면 높이에 맞춰 행 간격과 세부 정보 간격을 줄여 전체 목록을 함께 표시합니다. 별도의 목록 페이지로 나누지 않으며, 매우 작은 화면에서는 같은 목록 안에서 세로로 스크롤합니다.

## 다운로드 속도와 동시 처리

미리 확정된 기본 학습 자료·공통 평가 자료·MIT 잔향 파일은 **하나의 대기열**에서 받습니다. 자료마다 대기·다운로드·무결성 검사·완료 상태와 진행량을 표시합니다. 아직 원본을 선정하지 못한 자료는 선정 대기로 구분하며, 다운로드가 끝난 것처럼 표시하지 않습니다.

**서버마다 파일 하나씩 동시에 받기 시작합니다.** 대기 파일이 있으면 한 번에 서버 한 곳에서만 파일을 하나 더 시작합니다. 추가 전후 여러 구간에서 전체 수신 속도를 측정하고, 관측된 속도 변동보다 개선 폭이 크면 늘린 수를 유지합니다. 5% 정도의 작은 개선도 꾸준히 나타나면 반영합니다. 이득이 확인되지 않으면 마지막으로 효과가 있었던 수로 돌아가며, 이미 시작한 파일은 끝까지 받습니다. 재시도로 새 작업을 줄일 때는 해당 서버에만 적용합니다.

자동 모드는 기본적으로 최대 16개까지 탐색합니다. 이는 과도한 연결을 막는 안전 상한이며 모든 환경의 최적값을 뜻하지 않습니다. 서버를 시작하기 전에 PowerShell에서 상한을 1~32개로 조정할 수 있습니다.

```powershell
$env:KOWW_DOWNLOAD_MAX_WORKERS = '16'
```

고정된 수로 받으려면 `KOWW_DOWNLOAD_WORKERS`를 1~32의 정수로 지정합니다. 예를 들어 `$env:KOWW_DOWNLOAD_WORKERS = '4'`는 항상 최대 4개로 처리하며, `'auto'`로 바꾸면 자동 조절로 돌아갑니다. 지정하지 않아도 자동 모드입니다. 화면의 자료별 진행률과 완료 수는 각 자료 행에서 확인할 수 있습니다.

기존 부분 파일·캐시·해시 검사량은 새 다운로드 수신량에 포함하지 않습니다. 파일의 출처·크기·해시·이어받기·잠금과 이후 처리 순서는 유지합니다. 단일 파일은 한 연결로 받으며, 관측 시간이 짧거나 대기 파일이 적으면 자동 조절 효과가 제한됩니다. 대용량 원본은 선정·변환·검증 후 다음 묶음을 받는 저장 공간 한도를 지킵니다. FMA 곡별 미리받기도 유지하므로 모든 원본을 한꺼번에 쌓아 두지는 않습니다. 자동 조절은 현재 상태에 대응하는 방식이며 정확한 최적값이나 일정한 속도 개선율을 보장하지 않습니다.

## 중단하고 이어서 하기

중앙의 **일시정지**는 파일을 쓰는 작업을 강제로 끊지 않고 현재 단계를 마친 뒤 멈춥니다. 멈춘 작업은 같은 위치의 **재개**로 이어갑니다. 서버 창을 갑자기 닫아도 이미 실행 중인 한 단계는 계속 돌아갈 수 있습니다. 다시 열면 실제 PID와 생성 시각, 완료 기록을 확인해 중복 실행을 막습니다.

컴퓨터가 꺼져 작업이 중단됐다면 같은 작업 폴더에서 `koww web`을 실행하고 **이어서 진행**을 누르세요. 다운로드는 부분 파일을, 생성은 검증한 완료 발화를, 특징·학습·평가는 해시가 맞는 재개 기록을 사용합니다. 평가는32세션마다 점수를 저장하므로 중단 직전 일부는 다시 계산할 수 있습니다. 다른 살아 있는 작업의 잠금은 해제하지 않으며, 코드·설정·입력이 달라진 실험을 같은 작업으로 이어붙이지 않습니다.

진행률은 해당 작업에서 확인한 실제 수량입니다. 완료 단계 수를 전체 작업 시간의 비율로 표시하지 않습니다. 남은 시간은 현재 단계에서 실제 처리 속도를 측정할 수 있을 때만 표시하며, 검수 대기와 아직 측정하지 않은 다음 단계까지 포함한 전체 완료 시간은 아닙니다.

기준 목소리·호출어·유사어 생성, **증강·특징 추출**, **모델 학습**, **성능 평가**, **학습 결과 정리**는 같은 항목명·상태·게이지를 사용합니다. 실제 수량을 아직 받지 못한 준비·검증·정리 중에도 대기형 게이지를 표시하며, 실행 중인 작업에는 **3초 주기의 초록색 회전 아이콘**을 표시합니다. 수량이 확인되면 같은 행에서 실제 진행량으로 바뀝니다. 일시정지와 오류는 그 상태로 표시하고, 완료 단계 수를 음원 처리율로 바꾸지 않습니다.

학습 시작 시에는 서버의 `training_preparation` 기록에 따라 특징 자료 검증·장치 선택·모델 초기화·GPU 자료 적재 상태를 표시합니다. GPU 적재량이 확인되면 KiB·MiB·GiB 단위의 실제 처리량을 보여줍니다. 준비 기록이 끝나면 학습 갱신 횟수로 전환하며, **0회 학습**을 임의로 준비 중이라고 표시하지 않습니다. 성능 평가는 음원 검증·채점·결과 정리를 구분하고, 채점 수가 100%여도 실제 정리가 끝나기 전에는 완료로 표시하지 않습니다.

## 라이브러리 업데이트

웹 서버를 실행한 창에서 Ctrl+C로 종료한 뒤 저장소 폴더에서 실행합니다. 작업이 진행 중이면 먼저 **현재 단계 후 일시정지**를 누르고 해당 단계가 끝날 때까지 기다리세요.

```powershell
git pull --ff-only
. .\scripts\Use-ProjectStorage.ps1
.\.venv\Scripts\python.exe -m pip install --no-deps .
.\.venv\Scripts\python.exe -m korean_openwakeword web
```

기존 자료·모델·평가 결과는 삭제하지 않습니다. 한 단계도 실행하지 않은 웹 프로젝트는 설정과 실행 기록을 확인한 뒤 새 코드로 연결합니다. 이미 실행한 실험의 코드 결합은 자동 해제하지 않으며, 확대된 평가 구성을 적용하려면 새 실험을 만드세요. 과거 평가 결과를 새 결과로 덮어쓰지 않습니다. 위 명령은 라이브러리만 업데이트하며 기존 PyTorch 설치를 변경하지 않습니다.

## 큰 규모와 성능 확인 범위

새 웹 프로젝트는 `automatic_v3` 자료 준비 정책을 저장합니다. 시험 모델용과 상용 모델용도 기본 출처를 직접 내려받아 추가 경로를 입력할 필요 없이 목표량 준비를 이어갑니다. 제공 학습·평가 배경 자료는 자동 검사 후 연결하며, 직접 추가한 자료의 검수는 유지합니다. 공간 부족·서버 오류·후보 소진·이용 조건 확인이 필요한 경우에는 원인과 부족분을 표시하고 멈춥니다. 키가 없거나 `automatic_v1`·`automatic_v2`인 기존 프로젝트의 저장 방식과 완료 기록은 유지하며, 직접 확보한 자료와 기존 승인 기록을 연결하는 기능도 유지합니다.

이전 버전에서 만든 프로젝트는 기존 자료 목록·준비 정책·완료 기록을 유지합니다. 새 자동 준비 방식을 사용하려면 새 프로젝트를 만드세요. 검수한 YODAS2 샘플의 출처 적합성 판단은 앞으로 내려받을 모든 음원의 내용 승인과 구분합니다.

같은 파일을 복제하거나 2,000시간을 3,500시간으로 기록하지 않습니다. 상용 원본은 별도 특징 배열로 만들며, 원본 대응표가 없는 기존 숫자 자료와 시간을 단순 합산하지 않습니다. 이미 검증한 원본·다운로드·전처리 기록은 조건과 해시가 맞을 때 재사용합니다. `KOWW_CACHE_ROOT`로 지정한 캐시도 보존합니다.

세 규모 모두 같은 평가 호출어와 비호출 음원으로 공통 평가를 진행합니다. 기본 장치는 학습 도구 준비에서 선택한 장치입니다. 평가가 시작되기 전이나 일시 정지·실패로 멈춘 상태에서는 평가 화면에서 장치를 다시 선택한 뒤 **재개**할 수 있습니다. 같은 장치와 설정의 중간 결과가 있으면 이어서 평가하고, 계산 조건이 다르면 기존 결과를 보존한 채 별도 폴더에서 평가합니다. GPU 평가에서는 실제 CUDA 실행을 확인한 뒤 최대 128개 음원을 묶어 채점하고, 임계값에서 0.001 이내인 점수가 있는 음원은 CPU로 다시 확인합니다.

화면의 게이지는 완료한 음원 수와 전체 수를 표시하며3초마다 갱신합니다. 긴 비호출 음원은 짧은 호출 음원보다 오래 걸리므로 파일 수의 비율이 남은 시간의 비율은 아닙니다. 사전 검증 중에는 검사 중으로 표시하고, 음원 채점100% 이후에도 통계·파일 저장이 끝나기 전까지 결과 정리 중으로 표시합니다.

결과 정리 중에는 **학습 결과 정리**라는 공통 진행 행을 표시하고, 완성된 결과가 준비되면 넓은 결과 화면으로 전환합니다. 결과 화면은 요약과 간단한 목록을 먼저 표시한 뒤 필요한 음원의 상세 점수만 읽습니다. 오디오 목록은100개씩 표시하며, 연속 재생은 선택한 조건의 전체 음원을 이어갑니다. 음성 번호를 입력하면 해당 위치로 이동합니다.

새 로컬 Studio 결과는 **`studio_reference_v1` 참조 방식**으로 이미 채점한 WAV를 그대로 사용합니다. 결과 페이지를 만들려고 평가 WAV 전체를 다시 복사하거나 합성하지 않습니다. 완료된 평가 기록과 결과 파일의 해시 연결을 확인하고, 재생 요청 시 서버가 허용된 원본 경로와 음원 해시를 검증해 제공합니다. 원본 경로를 담은 참조 목록은 직접 공개하지 않습니다. 원본 채점 WAV는 해당 프로젝트에 보관해야 하며, 이 결과 화면은 로컬 웹 서버를 통해 엽니다. 별도 파일로 옮길 수 있는 일반 `export_site` 내보내기는 기본적으로 WAV를 복사합니다. 기존 완료 결과와 평가 기록은 이 최적화 때문에 다시 쓰지 않습니다.

목표 충족 여부는 평가 당시 저장한 기준으로 판단합니다. **모델 비교 → 목표 비교**에서 성공률·오작동·반응 시간의 목표와 실제 결과를 확인하세요.

마이크 시험은 ‘마이크 연결’을 눌러 브라우저 권한을 허용한 뒤 입력 장치를 선택하고 시작합니다. 모델 연결 오류가 나면 ‘모델 연결 다시 시도’를 사용합니다. 브라우저가 마이크를 차단하면 주소창의 사이트 권한에서 허용한 뒤 다시 연결하세요.

결과 화면의 모델 번호는 표·오디오·소음별 성공률에서 동일하게 사용합니다. ‘모든 배경 순서대로’는 선택한 소음 크기와 울림을 유지하면서 환경소음·음악·다른 사람 말소리를 차례로 듣는 선택입니다. **조건별 성능**에서는 모델과 울림을 고른 뒤 소음이 커질 때 성공률이 어떻게 달라지는지 비교합니다. 상세 점수와 파일 정보는 접힌 항목에서 확인할 수 있습니다.

자동 준비 경로의 구현·작은 실제 파일 검증과 전체 목표량의 확보·정식 학습·전체 평가 완료는 다릅니다. 실제 완료는 해당 프로젝트의 기록으로 확인합니다. 첫 실행의 전체 시간은 미측정이며, 현재 단계의 실측 속도가 쌓인 뒤에만 남은 시간을 표시합니다.

공통 평가 결과만으로 독립 최종 평가나 다수 실제 화자의 성능을 검증했다고 판단하지 않습니다. 웹 흐름은 Final을 자동 해제하지 않습니다. 기준은 [학습 계획](../plan.md)과 [평가 가이드](LIBRARY_GUIDE.md#8-모델설정-확정-후-최종-평가하기)를 따릅니다.

## 중단·업데이트 후 이어가기

연결 끊김이나 시간 초과는 제한 횟수 안에서 자동으로 이어받습니다. 파일 손상·원본 변경·공간 부족은 원인을 표시하고 멈춥니다. 전송, 파일 검사, 압축 해제, 음원 변환은 서로 다른 작업으로 표시합니다. 속도와 남은 시간은 해당 작업의 실측값이며 전체 학습의 예상 시간이 아닙니다.

공통 평가의 FSD50K와 잔향 자료는 전체 압축파일을 내려받아 검증합니다. 끊긴 전송은 이어받고, 검증을 통과한 자료를 재사용합니다. 기존 프로젝트와 완료 기록은 보존합니다.

호환 업데이트를 적용할 수 있으면 **업데이트 적용**이 나타납니다. 이전 실행 기록을 백업하고 완료 자료를 확인한 뒤 코드만 연결합니다. 다운로드 순서·진행 표시를 바꾼 업데이트도 자료와 처리 결과가 같다는 버전별 검증을 통과해야 적용할 수 있습니다. 이후 **이어서 진행**을 누르세요. 남은 단계의 계산이나 설정이 달라진 업데이트는 기존 실험에 자동 적용하지 않습니다. 완료한 프로젝트는 그대로 열 수 있으며 다음 호출어 프로젝트를 만들 수 있습니다.

전체 소요 시간은 완료 시 고정합니다. 작업 처리·사용자 확인 대기·일시정지를 분리하며, 과거 기록에서 구분할 수 없는 시간은 기타 경과로 표시합니다. 작업 처리 시간은 확인된 작업 프로세스의 실행 시간이며 CPU 사용 시간만을 뜻하지 않습니다.

## 평가 결과와 마이크 시험

**학습 결과**에서는 **모델 비교 / 소음별 / 음원 / 기준**을 전환합니다. 모델 비교에서 **추천값 결과 / 평가 당시 결과**를 골라 새 추천과 최초 평가 결과를 구분해 봅니다. 조건별 수치와 목표 충족 여부는 **상세 결과**에서 확인합니다. **마이크 시험**에서는 학습된 모든 모델의 반응을 동시에 비교하며, 모델이 세 개라면 평균 앙상블도 함께 표시합니다.

새 학습의 시작값은 **감지 기준 0.5·연속 감지 1회**입니다. 공통 평가 후 저장된 점수로 **임계값 0.01–0.99를 0.01 간격으로, 연속 감지 1–6회를 모두 비교**합니다. 깨끗한 환경과 반응속도 기준을 지키고 **오호출이 시간당 1회 이하**인 후보 중 강한 소음과 잔향에서 평균 성공률이 높은 값을 고릅니다. 조건별로 같은 비중을 적용하고 가장 취약한 조건도 표시합니다. 필요한 조건이 없거나 추천 기준을 지키는 조합이 없으면 **추천 없음**과 이유를 표시하고 절충값을 따로 보여줍니다. 추천 기준과 기존 정식 채택 목표는 다릅니다. 정식 채택 오호출 목표인 시간당 0.1회와 최초 평가의 통계·오디오 반응은 유지하며 따로 표시합니다. [추천 기준](../plan.md#모델별-감지-설정-자동-추천)을 참고하세요.

마이크는 **모델별 추천값**이 준비되면 그 설정으로 시작합니다. 추천이 없는 모델은 기존 설정을 유지하며 화면에 표시합니다. 절충값을 자동 적용하지 않습니다. 각 모델에 적용된 감지 기준과 연속 감지 수는 반응 표에서 확인할 수 있습니다. **직접 설정**을 선택하면 같은 값으로 전체 모델을 시험합니다. 시험 중에는 설정을 바꿀 수 없으며, 중지 후 값을 바꿔 다시 시작합니다. **기본값으로**는 모델에 저장된 원래 시작값으로 돌아갑니다. 모델을 먼저 고르거나 별도로 저장하는 단계는 없습니다.

GPU 평가 점수의 추천값이 CPU 마이크 실행과 완전히 같은 판정을 보장하지는 않습니다. 별도 실행 검증이 끝나지 않은 추천은 **저장 점수 기준**으로 표시하므로 마이크 반응도 확인하세요. 기존 모델과 예시 모델의 감지 설정·평가 기록은 그대로 보존합니다.

시험 설정은 메모리에서만 사용하고 원래 프로젝트 설정·모델·평가 음원·점수를 변경하지 않습니다. 마이크 음성은 저장하거나 학습 자료로 사용하지 않습니다. 이전 모델 선택·감지 기준 비교 기록은 보존하며, 예전 화면 주소는 마이크 시험으로 연결됩니다. 파일 내보내기와 저장 점수 재비교가 필요한 경우 개별 명령을 사용할 수 있습니다.

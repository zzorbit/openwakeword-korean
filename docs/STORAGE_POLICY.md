# 저장 위치 안내

학습 자료를 둘 드라이브와 폴더는 사용자가 선택합니다. **SSD와 HDD 모두 사용할 수 있습니다.** 자료가 들어갈 실제 위치와 여유 공간을 먼저 확인하세요.

## 무엇이 어디에 저장되나요?

| 항목 | 기본 위치 |
| --- | --- |
| 생성 음성·학습 데이터·학습 결과 | `koww init --output`으로 만든 프로젝트 폴더 |
| 공개 자료 다운로드 | 다운로드 명령의 `--output`으로 지정한 파일 |
| 모델 다운로드·임시 파일 | 프로젝트 폴더의 `cache` |
| 설치 스크립트를 사용한 다운로드 캐시·임시 파일 | 저장소 폴더의 `storage/runtime_cache` |

프로젝트별 저장 위치는 다음 명령으로 확인합니다.

```powershell
koww storage --project projects/bora/project.json
```

## 설치할 때의 저장 위치

Windows PowerShell에서 저장소 폴더로 이동한 뒤, 패키지를 설치하기 전에 실행하세요.

```powershell
. .\scripts\Use-ProjectStorage.ps1
```

이 스크립트는 설치 파일·모델 다운로드 캐시·임시 파일을 저장소 안에 모아 저장하도록 설정합니다. **현재 PowerShell 창과 그 창에서 실행한 프로그램에만 적용**됩니다. 창을 닫았다가 다시 열면 필요한 작업 전에 다시 실행하세요. 시스템 전체 설정을 바꾸지는 않습니다.

## 여러 호출어에서 다운로드 캐시 공유하기

여러 프로젝트가 같은 Qwen 모델을 내려받지 않도록 캐시 위치를 지정할 수 있습니다. 다음은 저장소의 `shared/cache`를 사용하는 예시입니다.

```powershell
$env:KOWW_CACHE_ROOT = Join-Path (Get-Location).Path 'shared/cache'
koww storage --project projects/bora/project.json
```

`Use-ProjectStorage.ps1`도 이 값을 설정하므로, 공유 캐시를 직접 지정하려면 **스크립트를 실행한 다음** 위 명령을 사용하세요. 공개 음성·소음 자료는 `shared/`에 한 번 내려받고 각 프로젝트의 자료 목록에서 연결해 재사용할 수 있습니다.

## 대규모 자료의 중복 저장 줄이기

새 웹 프로젝트는 `automatic_v3`의 `canonical_flac_only_v1` 정책을 사용합니다. **공개 학습 비호출·소음·잔향의 학습용 변환본을 16kHz 모노 PCM16 무손실 FLAC으로 보관**합니다. 대규모 AudioSet·MLS·FMA full·YODAS2의 새 원본은 검증 후 정리하고, 공식 예제 소음·MIT RIR의 공유 기본 다운로드와 묶음은 보존합니다.

1. 제공자 원본을 내려받아 크기·해시와 출처를 확인합니다.
2. 기존 전처리와 같은 학습용 PCM을 만들고 FLAC에 저장합니다.
3. FLAC을 다시 읽어 PCM 값·길이·해시가 같은지 확인하고 완료 기록을 남깁니다.
4. 검증한 새 대규모 자료의 전용 원본·임시 묶음과 중복 변환 WAV만 정리합니다.

검증 실패·중단 중에는 정리하지 않습니다. 완료한 FLAC과 원본 ID·원본 해시·제공자 정보·이용조건·변환 기록을 보존하고, 재개 시 확인해 재사용합니다. 기존 사용자 자료·외부 파일·이전 캐시·완료 기록을 자동 변환하거나 삭제하지 않습니다. 기존 검사에서 거부한 음원과 공유 중인 원본도 남깁니다. 생성 TTS와 평가 WAV도 이번 변경 대상이 아닙니다. `automatic_v1`·`automatic_v2` 프로젝트와 개별 다운로드 명령은 기존 보관 방식을 유지합니다.

새 상용 웹 프로젝트는 `automatic_v3`에 `fma_acquisition_policy: per_track_flac_prefetch_v1`을 추가합니다. FMA 음악은 한 곡씩 다운로드·변환·검증하고, 변환 중에는 다음 곡 1개만 미리 받습니다. 정상 변환·PCM 검증·보존 기록 저장을 마친 새 단독 소유 MP3만 정리하므로 선정 곡 전체를 MP3로 임시 보관하지 않습니다. 품질 검사에서 거부한 원곡은 보존하며, 재개 시 FLAC 또는 거부 원곡의 완료 기록을 확인합니다. 이 키가 없는 기존 프로젝트는 일괄 처리 방식을 유지하며, 독립 `download-fma` 명령으로 받은 원본 MP3와 이전 캐시는 정리하지 않습니다.

**FLAC 보관은 학습 입력을 유지하고 중복 보관만 줄입니다.** 기존 학습용 PCM을 손실 없이 저장하지만 고해상도 원본 자체를 보존하는 방식은 아닙니다. 원본을 다른 전처리 설정으로 다시 변환하려면 재다운로드해야 합니다. 보관 방식만 바꾸면 자료 시간·선정 목록·증강·특징 계산·학습 설정과 다운로드 전송량은 바뀌지 않습니다. 자료 목표 시간을 줄이는 것은 이 보관 방식과 별도의 선택입니다.

## 상용 모델용 저장 용량 계산

상용 기본값은 **비호출 5,000시간·호출어 100,000개·R5·모델당 100,000회 학습·CNN128 세 모델**입니다. 비호출은 AudioSet 1,500시간·MLS 1,500시간·FMA full 500시간·YODAS2 한국어 1,500시간으로 유지합니다.

**전체 필요 용량과 작업 중 동시 최대 용량은 아직 확정되지 않았습니다.** 종전 699GB 비교 예산은 TTS·평가 사본 등 전체 파일을 포함하지 못했고, 1.0~1.2TB 권장값에도 항목별 근거가 부족했습니다. 두 수치를 전체 필요량으로 사용하지 않습니다. 임의로 더했던 작업·예비 공간 **33,285,996,544B**도 제외했습니다.

### 계산식과 적용 조건

- **음원:** `시간 × 3,600 × 16,000 × 2B`. 5,000시간은 PCM 데이터만 576GB입니다. 실제 FLAC은 완료 기록의 파일 크기를 합산해 이 환산값을 대체합니다. 소수 표본의 압축률을 전체에 적용하지 않습니다.
- **특징:** 한 행은 `16 × 96 × float32 4B = 6,144B`입니다. 비호출의 명목 행 수는 `ceil(전체 초 / 2)`이고 실제로는 원본 파일마다 올림하므로 행이 추가됩니다. 호출어는 `100,000 × R5`이며 50만 개의 증강 WAV를 별도로 보관하지 않습니다.
- **TTS:** 기본 `max_new_tokens=256`, 12.5프레임/초에서 실패 시도는 최대 약 20.48초, 성공 음원의 기술 검사 제한은 8초입니다. 목표 슬롯 112,024개(호출어 Train·Validation·Final 110,000개 + 유사어 2,000개 + 파일럿 24개)가 각각 실패 2회 뒤 성공 1회로 완료되고, 합성 참조 140개를 보존하는 경우를 계산했습니다. 헤더·재표본화 경계 1샘플도 포함합니다. 이는 평균 예상량이 아닙니다. 실제 1,000개 생성 사례의 성공 음원 평균 길이는 0.7984초였으나 전체 규모에 외삽하지 않습니다.
- **평가:** 공통 평가는 무잔향 80,000회 + 잔향 32,000회입니다. 독립 Final의 `5,000 × (1 + 3범주 × 5 SNR × 5구간) = 380,000회`는 [수동 가이드](LIBRARY_GUIDE.md)의 명령 예시이며, 자동 최종 평가 기준이나 동결된 시험 규격이 아닙니다. 원본과 조건을 확정하면 저장 계산도 다시 합니다.
- **Qwen·설치 환경:** 두 Qwen 저장소의 고정 배포 파일은 각각 4,520,163,832B·4,544,229,700B입니다. 저장소마다 tokenizer 사본이 있으므로 둘 다 계산했습니다. Python 환경은 의존성 설치 파일 실측에서 이전 라이브러리 패키지를 현 배포본의 실측 크기로 교체해 합산한 참고값입니다. 공유 Python·설치 다운로드·설치 임시 파일은 포함하지 않습니다.
- **RIR:** MIT 학습 원본 270개는 8,374,902B, 동일한 학습 PCM으로 변환하고 재읽기 검증을 마친 FLAC은 1,554,203B로 합계 9,929,105B입니다. 학습용 MIT 원본은 개별 파일로 받습니다. 별도로 공통 평가용 OpenSLR28 ZIP 1,311,166,223B는 기본 자료 다운로드 행에 이미 포함되어 다시 더하지 않습니다. 그 안의 공통 평가 RIR 80개 WAV 2,051,520B는 공통 자료 해제 원본 행에 포함합니다.
- **체크포인트·점수:** 체크포인트에는 가중치뿐 아니라 optimizer·샘플러 상태도 들어갑니다. 위 9개 크기는 명목 풀 크기로 수행한 메모리 직렬화 시험입니다. 실행 모델 사본은 기존 CNN128 세 ONNX의 실측 합계 1,946,271B를 학습 결과·원 bundle·선정 bundle에 각각 보존하고, frontend 두 파일의 실측 합계 2,414,536B도 세 위치에 보존하는 경우입니다. 가이드의 평가 시나리오에서 세 모델과 평균 점수의 float32 데이터만 계산하면 약 611.424MB이며, 실제 압축 파일·JSON·원시 점수 캐시·선택 결과 사본의 합계는 별도 확인해야 합니다.

| 연속 비호출의 추가 길이 | 유효 30·100시간 이외의 스트림별 워밍업·말미·WAV 헤더 |
| 독립 Final 원본·추가 자료 | 학습·공통 평가와 분리한 실제 출처, 다운로드 묶음과 해제본, 최종 RIR 조건 |
| 점수·보고서·보조 파일 | 실제 NPZ·JSON·원시 점수 캐시, 검수 HTML·임시 색인·receipt와 추가 내보내기 사본 |
| 다운로드·변환 중 동시 보관량 | 현재·다음 곡, 다운로드 묶음·해제 원본·변환 FLAC, 검사 거부 원곡의 누적량 |
| 설치 중 추가 파일 | 선택한 OS·CPU/CUDA 배포판의 설치 다운로드·캐시·임시 파일 |
| 실제 드라이브 사용량 | 파일 할당 단위·복사 방식·기존 자료·백업·중단·재실행 이력 |

미확정 항목에 임의의 여유 용량을 더하거나 0B를 넣지 않습니다. 기존에 사용하던 FMA 작업 여유 8GiB도 다운로드·해제 크기의 상한이 아닙니다. 제공자가 공개한 압축 묶음 크기로 압축 해제한 원본의 크기를 대신하지 않습니다.

FMA 목록은 CSV만 선택 다운로드하므로 메타 ZIP 전체 358,412,441B를 더하지 않습니다. CSV 압축 임시본 19,496,284B는 해제 후 삭제하며 처리 중 최대량에만 해당합니다. 보충 candidate가 만드는 추가 CSV, AudioSet 목록·ontology, MLS의 실제 사용 언어별 TXT·README, YODAS의 선정 shard별 duration·text는 실제 경로와 공유 여부로 합산합니다. 공유 metadata hardlink는 파일 경로 수만큼 중복 계산하지 않습니다.

**작업 중 동시 최대량은 단계별로 따로 계산합니다.** 각 단계에서 이미 보존한 파일에 그때 함께 존재하는 다운로드·해제·변환·내보내기 파일을 더하고, 그중 가장 큰 값을 확인합니다. 전체 전송량·완료 후 보관량과 구분합니다. 다음 단계의 실제 입력과 추가 바이트를 확인한 뒤 진행하며, 전체 Final 규격과 미확정 파일이 정해지기 전에는 새 총량을 제시하지 않습니다. 기존 자료는 보존하므로 라이브러리 업데이트만으로 현재 사용 공간이 줄어들지는 않습니다.

### 실제 표본의 압축 크기

기존 PCM과 FLAC을 다시 읽은 PCM이 같은지 확인한 표본입니다. 아래 비율은 전체 자료의 예상 압축률이 아닙니다.

| 표본 | 오디오 길이 | PCM 데이터 | FLAC 파일 | PCM 대비 크기 |
| --- | ---: | ---: | ---: | ---: |
| MLS 30개 | 459.32초 | 14,698,240B | 7,705,913B | 52.43% |
| FMA 원곡 1개 | 144.90초 | 4,636,908B | 2,977,227B | 64.21% |
| YODAS2 10개 | 4,259.57초 | 136,306,104B | 86,730,397B | 63.63% |

YODAS2는 기존 20개 중 10개가 종전과 같은 클리핑 검사에서 거부됐으며 원본을 보존했습니다. 검사 기준을 완화해 압축 수량을 늘리지 않습니다.

## 용량 확인과 자료 이동

압축 파일과 압축 해제한 음원, 증강 특징 파일, 평가 오디오는 각각 공간을 사용합니다. 설치된 Python의 위치와 학습 자료의 위치는 별개입니다.

폴더를 옮길 때는 **원본 보존 → 복사 → 파일 크기·SHA256 확인 → 설정의 경로 확인 → 새 위치에서 사용 확인** 순서로 진행하세요. 확인이 끝나기 전에 원본을 지우지 않습니다. 실행 중인 학습이 사용하는 파일은 이동하거나 정리하지 않습니다.

일시적으로 더 빠른 드라이브를 사용할 때도 용량 한도와 작업 후 정리 방법을 정해 두세요. 라이브러리는 성능을 이유로 자료를 다른 드라이브에 자동 복사하지 않습니다.

전체 학습 절차는 [호출어 학습 가이드](LIBRARY_GUIDE.md)를 참고하세요.
